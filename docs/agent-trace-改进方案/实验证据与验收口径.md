# Agent 改进数据服务：实验证据与验收口径

本文说明前置实验、拟议机制、试点范围和评价方法。前置实验属于已完成的局部验证；试点指标属于待验证的预设门槛。三类实验分别检验辅助机制、离线转换和存储布局，结论按各自范围使用。

## 实验一：观测与记忆辅助对照

### 对象与基线

ARC-AGI-3 是交互式视觉推理基准，Agent 通过游戏动作探索未知规则。VISTA 是提供工具、笔记与上下文交接的运行框架。2026-10-26 报告快照中的 5 个已完成游戏，每个游戏对全开组和关闭组各运行 3 轮，共 15 对；同序号运行配对，不表示随机过程完全相同。

两组使用相同的 GPT-6 Luna 模型、推理设置、上下文阈值和调度队列，从第 1 关开始，按 1,000 动作截断。关闭组的提示、工具定义、输出和交接行为与 VISTA 上游基线一致；全开组增加 11 项观测与记忆辅助，包括画面变化、历史失败提示、带回合引用的规则和交接约束。两组模型参数保持相同。

### 得分与结果

相对人类动作效率（RHAE）结合过关和动作效率：已过关的单关效率分为 `min((人类基线动作数/Agent动作数)^2, 1.15)`，未过关计 0；按从 1 开始的关号加权，并以过关情况限制总分上限，报告缩放为 0–100 分。先对每个游戏的 3 轮取均值，再对 5 个游戏等权平均。它衡量游戏表现，与经营分析任务正确率分别统计。

| 指标 | 关闭辅助基线 | 11 项辅助全开 |
|---|---:|---:|
| 平均 RHAE | 12.7 | 33.4 |
| 过关数合计 | 53 | 81 |
| 15 对中得分更高的全开运行 | — | 13 对 |

实验未做单项消融；结果支持辅助组合在这组游戏中的效果。自动经验生成、跨独立业务任务复用、存储贡献和生产收益分别验证。

**来源**：《VISTA 观测与记忆辅助在 ARC-AGI-3 上的对照实验报告》，2026-10-26，第 1、2.1、2.3、3.3 节；内容 SHA-256：`c02f98bbdb24a520880252092954e2c2562c3fdf565eabe7ec2ede9539a9fdf9`。该报告为内部实验原始材料；本文提供独立可读的条件、结果和边界摘要。公开计分定义见 [ARC Prize 官方方法](https://docs.arcprize.org/methodology)。

## 实验二：离线监督样本转换

### 输入与两条路径

从 SWE-smith 和 SWE-Gym 两个公开编程任务轨迹集的固定分片各取前 8 条，每条选取一个已有完整工具调用与返回历史的决策，共 16 个单决策样本。这是确定性契约用例，不是随机抽样；目标集中于早期编辑工具调用。

1. **直接路径**：冻结源记录 → 协议规范化 → 选定决策 → 用固定模板和分词器构造输入、目标与监督标签。
2. **重建路径**：同一决策 → 仿 OpenTelemetry 的事件记录及附属顺序、内容引用 → 重建决策 → 使用相同模板、分词器和监督规则生成样本。

OpenTelemetry 是观测数据标准；本实验只在离线文件中模拟其记录组织，没有经过真实 OpenTelemetry Protocol 传输、Collector 采集组件或数据库。使用 Qwen2.5-Coder-0.5B-Instruct 对应分词器，未进行模型前向计算和参数训练。

### 检查结果与证据等级

16 个样本的规范化语义、输入分词编号、监督标签、目标起点和有效监督数均一致。输入合计 31,323 个分词单元，有效监督 948 个。相同输入的重复物化产物保持确定性。

按“公开轨迹、约定配方”要求，16 个样本可用于构造监督；按“精确复现原始模型请求”要求，16 个均因缺请求快照而拒收。该结果说明用途准入需要区分证据要求，也说明转换一致不能证明原始请求完整。真实摄入保真、后段决策覆盖、工具执行和训练收益仍需独立验收。

**来源**：《离线 Trace-to-Training 契约：设计、实现与验收结论》，2026-11-12，第 2–4、6 节；内容 SHA-256：`391c3c38cfbc4e55544afcbf237cb0b3425240e0c544630d92f49c3ddeef3c73`。该报告为内部实验原始材料。

## 实验三：长载荷存储布局

### 前置发现

实验比较 openGauss、ClickHouse 和 XStore 上的同表、分表、完整表加窄表、外置对象布局，使用确定性投影数据与受控载荷，测试写入、列表、详情、完整执行记录、批量读取和故障一致性。

同为 80 MiB 载荷，40 个 2 MiB 对象时外置布局最快，1,280 个 64 KiB 对象时最慢。外置后的空间收益也取决于库内压缩能力：原实验中 openGauss、ClickHouse 总占用分别增至同表的 2.884、6.921 倍，XStore 为 0.787 倍。以上为特定引擎、版本、数据和主机上的结果，不作为通用阈值。

各请求流改为分进程后，首轮大量前台请求丢弃基本消失，表明早期明显干扰主要来自压测客户端争用。该实验范围内，分表与外置的前台隔离收益没有得到支持。

### 试点选型方法

| 数据消费 | 首先比较的布局 | 决策指标 |
|---|---|---|
| 任务过滤、版本比较 | 结构化索引、窄字段读取 | 查询计划、扫描量、尾延迟 |
| 详情、近期上下文与证据读取 | 同表与库内分表 | 详情延迟、连接成本、压缩率 |
| 低频大产物、长期归档 | 库内与外置对象 | 对象数量与大小、请求次数、总空间及恢复成本 |
| 训练样本批量导出 | 上述布局的批量读路径 | 吞吐、解压与重建成本、交付完整性 |

在目标引擎和真实载荷分布上测量后冻结布局。外置方案关联事件引用、对象目录和内容哈希，验证对象缺失、引用失败、重复写入与补偿；内容不可用时拒绝相关交付并报告状态。

**来源**：《Agent Trace JSON 存储阶段三组内汇报：长载荷的四种布局》，2026-10-08，第 1、7、10–16 节，含后续修订结论；内容 SHA-256：`bfda85b28d4f77228d8586e39b9fc106859f468c12ecef6183efe501da6074f4`。该报告为内部实验原始材料。

## 与既有管线的差异及验证

Agent Lightning v1.0 已提供训练器、模型请求网关和运行控制器，将真实运行框架中的交互组织为训练数据，包含数据清理和奖励投机防护示例。其 Agent Lightning Skill 还支持修改提示词、工具、工作流、模型和配置，并用基准比较效果。因此，运行与训练解耦、使用执行反馈、支持框架改进均属于已有能力。

本方案提出的增量设计如下，属于待比较验证的工程机制；公开材料未提到某项能力，不作为其不存在的证据。

| 增量设计 | 具体产物 | 验证方式 |
|---|---|---|
| 同一记录按用途分别准入 | 用途、准入状态、证据缺口、拒收理由、规则版本 | 在相同输入上比较缺陷检出与误拒情况 |
| 保留用途相关的可核验关联 | 输入引用、接口、结果证据、环境及模型版本 | 注入缺失、乱序、错配和版本冲突，检查阻断范围 |
| 来源至改进效果的关联 | 来源 → 转换 → 数据集／记忆／框架版本 → 评测结果 | 追溯覆盖率、重建与撤回演练、加工工时 |

数据管理对照拟采用固定版本 Agent Lightning 的采集、清理与训练数据构造能力，接入相同导出适配和人工复核流程；实验组增加上述用途检查和关联机制。两组使用相同输入、目标格式及判定标签，记忆和框架材料使用相同转换器；适配成本单列。冻结 40 个有效用例和 40 个已知缺陷用例；缺陷覆盖截断、乱序、接口缺失、结果错配、未来评价信息混入、采样版本不符、对象缺失、授权缺失 8 类。目标是在这些已知类别上缺陷检出率至少 95%、有效用例误拒率至多 5%。这项检查只覆盖定义的用例范围。

**公开比较来源**：[Agent Lightning 官方 README](https://github.com/microsoft/agent-lightning/blob/2070bad5113e52f1aa2e5bdba822d4b24b197c05/README.md)；[Agent Lightning Skill](https://github.com/microsoft/agent-lightning/blob/2070bad5113e52f1aa2e5bdba822d4b24b197c05/skills/README.md)，固定提交 `2070bad5113e52f1aa2e5bdba822d4b24b197c05`，访问于 2026-11-13。

## 试点设计与验收口径

### 范围与阶段

- **业务范围**：一个经过授权、脱敏的企业经营数据库快照，包含订单、退款、费用相关数据；工具只读。三个任务类别为指标查询、关联汇总和异常解释，每类 30 项，共 90 项。
- **数据划分**：每类 10 项开发、20 项评测。按业务问题、查询模板、任务来源及时间去重隔离；相似任务作为一组划分。开发阶段使用的时间分区与封存评测分区分离。评价答案及测试专用信息存于独立权限域。
- **改进材料**：开发任务采集多候选和人工纠正，构造监督及偏好样本、经验和框架回归集。监督与偏好训练先检验交付格式及小规模可行性；近端及组相对策略优化首期只测试重新采样和奖励记录适配。训练算力、训练成本和后续能力收益独立立项验收。
- **比较方法**：记忆实验固定模型和框架；框架实验固定模型和经验库；训练实验固定基础模型来源、工具及评测框架，并记录更新后的权重版本。推理调用次数、分词预算、计价表与停止条件一致。
- **发布评价**：在开发集选定一个发布候选，冻结其权重、记忆、框架及规则版本，再与原基线对比。60 个封存任务各重复 3 次，两组均为 180 次运行。开发阶段比较过的其他候选不参与封存集择优；增加候选需处理多重比较或启用新评测集。

### 预设目标

下列数值是试点设计门槛，尚无业务实测支撑。启动时由业务与技术负责人确认、在封存评测前冻结。业务收益须经试点测量。

| 指标 | 定义 | 预设目标 |
|---|---|---|
| 任务正确率 | 执行成功、数值对账、业务口径核验均通过的运行数／总运行数 | 比固定基线提高至少 5 个百分点 |
| 人工复核工时 | 复核人员不知道候选版本，按运行计有效审阅和修订时间 | 每次运行的平均工时下降至少 20% |
| 每个正确任务推理费用 | 全部运行及重试的推理费用之和／正确运行数；含检索和使用经验所需的模型调用 | 不高于基线 |
| 来源可追溯率 | 来源、转换规则、版本、结果证据均可定位的交付产物数／交付产物总数 | 100% |
| 数据检查能力 | 上述固定用例内的缺陷检出率、有效用例误拒率 | 至少 95%、至多 5% |
| 权限与交付检查 | 检查集覆盖的越权读取、敏感字段导出、对象引用失效 | 全部阻断并报告原因 |

推理费用使用冻结价表；训练、数据准备和框架优化的一次性费用单列，另行计算预期任务量下的摊销成本。没有正确运行时，每个正确任务费用视为不可验收。

对同一任务的三次运行先聚合，以任务为单位进行配对重采样，报告差异的 95% 置信区间。正确率差异须达到 5 个百分点，且区间下界大于 0，才认定试点支持质量提升；其余业务门槛也需满足。未达到时记录为未确认收益，补充样本后重新验收。

## 风险与边界

| 风险 | 控制与边界 |
|---|---|
| 隐私泄露、训练用途越权 | 按采集、检索、训练、导出用途分别授权；脱敏后复核，保留撤销和删除传播记录；已训练权重单独处置，源数据删除与参数遗忘分别管理 |
| 评测泄漏、错误或伪造反馈 | 封存评价资产，按任务组隔离；执行、对账和人工证据分别关联，保留验证状态 |
| 错误经验传播、环境漂移 | 绑定适用条件和环境版本；回归失败时停用经验，保留来源与反例 |
| 奖励投机、框架过拟合 | 候选在隔离环境执行，评价器及参考答案保持只读隔离，使用封存任务验证 |
| 副作用、对象丢失与成本增加 | 首期仅只读查询；检验引用和内容一致性，失败阻断交付；训练与优化费用单独预算 |

验收覆盖定义的任务、检查和环境范围。生产多租户隔离、业务写操作、长期环境演化和持续训练收益需要后续专项验证。

## 术语

| 用语 | 本文含义 |
|---|---|
| 智能体（Agent） | 调用模型与工具完成多步骤任务的系统 |
| 执行记录（Trace） | 关联任务、模型调用、工具交互、环境反馈和结果证据的记录 |
| 企业经营分析 | 使用订单、退款、费用等业务数据进行指标查询、汇总和异常解释；本文商业场景的统一称呼 |
| 运行框架（harness） | 模型外部的提示词、工具、控制流程和上下文管理机制 |
| 经验记忆 | 从执行记录提取、带条件和证据、供推理时读取的数据 |
| 监督微调（SFT） | Supervised Fine-Tuning，学习给定输入下的目标输出 |
| 直接偏好优化（DPO） | Direct Preference Optimization，利用同一输入下候选的偏好监督更新模型 |
| 近端策略优化（PPO） | Proximal Policy Optimization，利用采样、奖励和策略约束更新模型 |
| 组相对策略优化（GRPO） | Group Relative Policy Optimization，利用同组候选的相对奖励更新策略 |
| 分词单元（token） | 分词器输出的模型输入或输出单位；监督标签决定哪些位置参与损失 |
| 准入 | 根据用途的证据、完整性、授权和版本要求决定数据是否可交付 |
| 血缘／来源关联 | 从原始记录经转换到产物及后续评价的可追溯关系 |

算法原始来源：[DPO](https://arxiv.org/abs/2305.18290)、[PPO](https://arxiv.org/abs/1707.06347)、[GRPO 所在 DeepSeekMath 论文](https://arxiv.org/abs/2402.03300)。
